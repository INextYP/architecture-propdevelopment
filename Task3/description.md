требования к безопасности


- Весь обмен информацией должен быть зашифрован (TLS).
- Партнёрская платформа не должна хранить персональные данные жильцов дольше, чем это необходимо для обработки текущего запроса (пока не будет выполнена операция идентификации и открытия доступа, например подъем шлагбаума)
- Платформа партнёра не должна иметь доступа к персональным данным, которые не нужны для выполнения функций (например, паспортные данные и финансовые сведения). Нужно чтобы данных хранились не более 5-10 секунд после получения ответа. После этого необходимо явно удалить их из любых хранилищ.

протоколы аутентификации и авторизации
- OAuth 2.0 для авторизации запросов API и разграничения прав доступа.
- HTTPS (TLS 1.3) для шифрования данных при передаче.

взаимодействие между системами предприятия и внешней платформой
- Запросы от партнерской платформы отправляются в контур, где происходит проверка прав жильцов, в ответ должен прийти id и право жильца на пользование
- Использование REST API с JSON-форматом передачи данных.
- Запросы API включают токен OAuth 2.0.
- Партнёрская платформа обеспечивает обработку запросов и управление оборудованием с предоставлением статусов устройств и действий.
